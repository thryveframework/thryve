## Prerequisites

Before you begin, ensure you have the following installed:

- **Windows (x86_64)**: Thryve builds on Windows only, for now
- **C++17 compatible compiler** (MSVC, GCC, or Clang)
- **CMake 3.15+** (optional, for building with CMake)
- **Rust toolchain** (if you need to build the FFI library yourself)

---

## Installation

### Option 1: Using Pre-built Distribution

Download it from Thryve's [release page](https://github.com/thryveframework/thryve/releases/latest), as .zip or .tar.gz: `thryve_ffi-<version>-windows-x86_64` has the C library, and `thryve-<version>-windows-x86_64` also has `Topology.exe`, which shows the task graph in graph mode. Unpacked, it has the following structure; this guide calls the unpacked folder `dist/`:

```
├── include/
│   ├── thryve.h        # C header (generated by cbindgen)
│   └── thryve_ffi.h    # C++ wrapper header (generated by build.rs)
├── lib/
│   └── thryve_ffi.lib  # The DLL's import library: link against it
├── bin/
│   ├── thryve_ffi.dll  # The shared library: ship it next to your executable
│   └── Topology.exe    # Only in thryve-<version>-…: keep it next to your executable too
├── LICENSE
├── COMMERCIAL.md
└── Topology-LICENSE    # Only in thryve-<version>-…
```

### Option 2: Building from Source

If you need to build the FFI library yourself:

1. **Clone the Thryve repository:**
   ```bash
   git clone https://github.com/thryveframework/thryve.git
   cd thryve
   ```

2. **Build the FFI library:**
   ```bash
   cargo build --package thryve_ffi        # Debug build
   # or
   cargo build --package thryve_ffi --release  # Release build
   ```

3. **Find the files the build produced:**
    - Headers: `crates/thryve_ffi/out/` (`thryve.h` and `thryve_ffi.h`)
    - DLL: `target/debug/thryve_ffi.dll` (or `target/release/`)
    - Import library: `target/debug/thryve_ffi.dll.lib` with the MSVC toolchain, `libthryve_ffi.dll.a` with the GNU one. Copy it into your project as `thryve_ffi.lib` to follow this guide's commands. (`thryve_ffi.lib` in `target/` is the static library: don't link it.)

## Project Setup

Create a new C++ project in your workspace:

```
my_thryve_app/
├── include/
│   ├── thryve.h        # Copy from thryve_ffi/out/ or dist/include/
│   └── thryve_ffi.h    # Copy from thryve_ffi/out/ or dist/include/
├── lib/
│   └── thryve_ffi.lib  # Copy from dist/lib/ (Windows)
├── src/
│   └── main.cpp        # Your application code
├── CMakeLists.txt      # Build configuration
└── README.md           # Project documentation
```

### Setting up the headers

Copy the headers from the FFI distribution to your project:

```bash
# From the Thryve FFI distribution directory (option 1: dist/)
cp dist/include/thryve.h my_thryve_app/include/
cp dist/include/thryve_ffi.h my_thryve_app/include/

# Or from the stable output directory (option 2: out/)
cp ../thryve_ffi/out/thryve.h my_thryve_app/include/
cp ../thryve_ffi/out/thryve_ffi.h my_thryve_app/include/
```

### Setting up the library

Copy the import library to your project:

```bash
# Windows (MSVC)
cp dist/lib/thryve_ffi.lib my_thryve_app/lib/
```

### Setting up the DLL (Windows only)

You need to copy the DLL to your application's output directory:

```bash
# Copy to your build output directory
cp dist/bin/thryve_ffi.dll my_thryve_app/build/
```

## Building

### Using CMake

Create a `CMakeLists.txt` in your project root:

```cmake
cmake_minimum_required(VERSION 3.15)
project(MyThryveApp LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

# Add include directory for headers (from thryve_ffi/out/ or dist/include/)
include_directories(${CMAKE_SOURCE_DIR}/include)

# Find the source files
file(GLOB SOURCES "src/*.cpp")

# Create the executable
add_executable(${PROJECT_NAME} ${SOURCES})

# Link against the Thryve FFI library
target_link_libraries(${PROJECT_NAME} PRIVATE thryve_ffi)

# On Windows, add the lib directory for the import library and copy DLL
if(WIN32)
    target_link_directories(${PROJECT_NAME} PRIVATE ${CMAKE_SOURCE_DIR}/lib)
    
    # Copy DLL to output directory (from dist/bin/)
    add_custom_command(TARGET ${PROJECT_NAME} POST_BUILD
        COMMAND ${CMAKE_COMMAND} -E copy_if_different
            ${CMAKE_SOURCE_DIR}/../dist/bin/thryve_ffi.dll
            $<TARGET_FILE_DIR:${PROJECT_NAME}>
        COMMENT "Copying thryve_ffi.dll to output directory"
    )
endif()
```

Build the project:

```bash
mkdir build && cd build
cmake ..
cmake --build . --config Release
```

### Using MSVC (cl.exe)

```bash
# Compile
cl /std:c++17 /Iinclude /EHsc src/main.cpp /link lib/thryve_ffi.lib

# Copy DLL next to executable (from dist/bin/)
copy ..\dist\bin\thryve_ffi.dll .
```

### Using MinGW (g++)

```bash
# Compile
g++ -std=c++17 -Iinclude src/main.cpp -Llib -lthryve_ffi -o my_app.exe

# Copy DLL next to executable (from dist/bin/)
cp ../dist/bin/thryve_ffi.dll .
```

## Writing Your First Plugin

A plugin is a unit of work that runs when the Thryve engine processes it.

### Step 1: Define your plugin callbacks

```cpp
// Plugin cleanup function — called once when the engine shuts down
extern "C" int my_plugin_cleanup(const void* core_ptr) {
    std::cout << "Cleaning up plugin data..." << std::endl;
    // Free your plugin's core data here.
    // Return ThryveStatus_Ok if it worked; any other value (for example
    // ThryveStatus_OperationFail) is logged to Error.log as a failed cleanup.
    return ThryveStatus_Ok;
}

// Plugin entry point — runs once when the engine starts. It fills in the result it's
// given, which starts empty: left alone, it reports nothing.
extern "C" void my_plugin_entry_point(ThryveTaskResult* result, void* core_ptr) {
    std::cout << "Plugin entry point called!" << std::endl;

    // Report that it started, in Main.log, or copy in a whole result:
    // *result = thryve_task_result_new("Started", "Plugin started", "Main");
    result->result_type = "Started";
    result->message = "Plugin started";
    result->log_file = "Main";
}
```

### Step 2: Create the plugin

```cpp
// Create configuration
ThryveConfig config = thryve_config_default();
if (!config) {
    std::cerr << "Failed to create config" << std::endl;
    return 1;
}

// Create context
ThryveCtx ctx = thryve_ctx_create(config);
if (!ctx) {
    std::cerr << "Failed to create context" << std::endl;
    thryve_config_free(config);
    return 1;
}

// Get the engine's connected PacketHandle from ctx (required for plugin
// creation). Do not create a standalone PacketHandle — it would not be
// wired to this ctx's engine.
ThryvePacketHandle packet_handle = thryve_ctx_get_packet_handle(ctx);
if (!packet_handle) {
    std::cerr << "Failed to get packet handle" << std::endl;
    thryve_ctx_free(ctx);
    thryve_config_free(config);
    return 1;
}

// Create the plugin
ThryvePlugin plugin = thryve_plugin_create(
    "MyType",             // type
    nullptr,              // plg_core_ptr (optional, can be NULL)
    packet_handle,        // tx (packet handle - REQUIRED)
    my_plugin_cleanup,    // clean_up callback
    my_plugin_entry_point // entry_point callback
);

if (!plugin) {
    std::cerr << "Failed to create plugin" << std::endl;
    thryve_packet_handle_free(packet_handle);
    thryve_ctx_free(ctx);
    thryve_config_free(config);
    return 1;
}
```

### Step 3: Add the plugin to the context

```cpp
// Add plugin to context (takes ownership of the plugin)
ThryveStatus status = thryve_ctx_add_plugin(ctx, plugin);
if (status != ThryveStatus_Ok) {
    std::cerr << "Failed to add plugin to context: " << (int)status << std::endl;
    thryve_plugin_free(plugin);  // Free if not added to context
    thryve_packet_handle_free(packet_handle);
    thryve_ctx_free(ctx);
    thryve_config_free(config);
    return 1;
}
std::cout << "Plugin added to context" << std::endl;
```

## Writing Your First Observer

An observer runs on a thread of its own. Its job is its whole loop: it waits for each notification sent to the observer, until the engine shuts the observer down.

### Step 1: Define your observer callbacks

```cpp
// Observer cleanup function — called once when the engine shuts down
extern "C" void my_observer_cleanup(const void* core_ptr) {
    std::cout << "Cleaning up observer data..." << std::endl;
}

// Observer job function — the observer's whole loop, called once on its own thread
extern "C" void my_observer_job(ThryveObserver observer) {
    // The obs_core_ptr the observer was created with
    auto* stats = static_cast<Stats*>(thryve_observer_core(observer));

    // Each notification sent to the observer, until the shutdown, when it's NULL
    while (ThryveNotif notif = thryve_observer_pop(observer)) {
        // The notif_core_ptr it was sent with: Thryve never frees it
        auto* reading = static_cast<Reading*>(thryve_notification_core(notif));
        stats->record(*reading);
        delete reading;
        thryve_notification_free(notif);
    }

    // The observer belongs to the engine: don't free it.
}
```

The shutdown calls `my_observer_cleanup` before `thryve_observer_pop` returns NULL. So if the clean-up frees the observer's core data, the job must not use it once `thryve_observer_pop` has returned NULL.

### Step 2: Create the observer

```cpp
ThryveObserver observer = thryve_observer_create(
    "MyType",             // type
    nullptr,              // obs_core_ptr (optional, can be NULL)
    packet_handle,        // tx (packet handle - REQUIRED)
    my_observer_cleanup,  // clean_up callback
    my_observer_job       // obs_job callback
);

if (!observer) {
    std::cerr << "Failed to create observer" << std::endl;
} else {
    std::cout << "Observer created" << std::endl;
    
    // Add observer to context (takes ownership of the observer)
    ThryveStatus status = thryve_ctx_add_observer(ctx, observer);
    if (status != ThryveStatus_Ok) {
        std::cerr << "Failed to add observer to context: " << thryve_last_error() << std::endl;
        thryve_observer_free(observer);  // Free if not added to context
    } else {
        std::cout << "Observer added to context" << std::endl;
    }
}
```

## Writing Typed Tasks

A typed task's job returns a value or an error, and the engine hands that result to whoever follows the task: Hash doesn't know LoadImg follows it, and LoadImg only knows it gets a digest. The [FFI README](../README.md#typed-tasks) has the whole model; this section shows it from C++.

A job is a C function pointer. A lambda that captures nothing converts to one, so jobs can be written in place. What a job needs comes through its `user_data`, which Thryve frees with the function given with it once the job has run, or if it never runs.

### A value, then a follow-up

```cpp
// Hash: its user data is the path; its value is the digest. Thryve deletes
// each once nobody needs it any more.
ThryveAdvTask hash = thryve_adv_task_create(
    "Hash", 2,
    [](void* user_data) -> ThryveOutcome {
        const auto& path = *static_cast<std::string*>(user_data);
        auto* digest = new std::uint64_t(std::hash<std::string>{}(path));
        return thryve_outcome_value(digest, [](void* value) {
            delete static_cast<std::uint64_t*>(value);
        });
    },
    new std::string("photo.png"),
    [](void* user_data) { delete static_cast<std::string*>(user_data); });

ThryveAdvHandle digest = thryve_packet_handle_send_adv_task(packet_handle, hash);

// LoadImg follows Hash: it gets Hash's digest, or Hash's error to pass on.
ThryveAdvHandle image = thryve_adv_handle_then(
    digest, "LoadImg",
    [](ThryveHandoff digest, void*) -> ThryveOutcome {
        if (thryve_handoff_is_error(digest)) {
            return thryve_outcome_error(thryve_handoff_error_code(digest),
                                        thryve_handoff_error_message(digest));
        }
        auto hash = *static_cast<const std::uint64_t*>(thryve_handoff_value(digest, 0));
        return thryve_outcome_value(new Image(decode(hash)), [](void* value) {
            delete static_cast<Image*>(value);
        });
    },
    nullptr, nullptr);
```

Each call that takes a handle uses it up, even when it fails, so a handle is never used twice. A handle you don't follow up on ends with `thryve_adv_handle_free`: the task still runs, and its result is let go.

### Several followers, joined

```cpp
// Thumbnail and Metadata read the one decoded image in place, as const.
ThryveFanoutGroup group = thryve_adv_handle_fan_out(image);
ThryveAdvHandle parts[2] = {
    thryve_fanout_then(group, "Thumbnail", make_thumbnail, nullptr, nullptr),
    thryve_fanout_then(group, "Metadata", read_metadata, nullptr, nullptr),
};
thryve_fanout_send(group);

// Report runs once both are done, with their values in order, or with the first error.
ThryveAdvHandle report = thryve_adv_handles_join(parts, 2, "Report", write_report, nullptr, nullptr);
thryve_adv_handle_free(report);  // nothing follows Report
```

Splitting work (`thryve_packet_handle_split_into`), forwarding (`thryve_adv_task_create_forward`) and cancelling (`thryve_adv_handle_cancel`) work the same way: see the [FFI README](../README.md#typed-tasks). [`examples/c_cpp/cpp/log_report.cpp`](../../../examples/c_cpp/cpp/log_report.cpp) runs a whole pipeline: a split, a join, a fan-out, and another join.

### Rules to keep in mind

- A value is read in place with `thryve_handoff_value`, and freed once the job returns. To keep it, or hand it on as the job's own value, take it with `thryve_handoff_take_value` first.
- A fan-out follower's value is shared: it's `const`, and can't be taken.
- Jobs run on Thryve's worker threads, several at a time.
- Free functions can run on the engine's own thread: they must only free memory.
- A C++ exception must never leave a job or a free function: catch it, and return `thryve_outcome_error` instead.

## Common Patterns

### Creating a Task

```cpp
// Define a task job function. It fills in the task's result, which starts empty:
// a job with nothing to report leaves it alone.
extern "C" void my_task_job(ThryveTaskResult* result, void* user_data) {
    std::cout << "Task job called with " << *static_cast<std::string*>(user_data) << std::endl;
    // Your task logic here
}

// Create the task. Its user data is a std::string, deleted once the job has run.
ThryveTask task = thryve_task_create(
    "MyTask",                       // name
    0,                              // priority: the engine caps it at max_priority (4 by default, 14 at most)
    my_task_job,                    // job callback
    new std::string("report.txt"),  // user data
    [](void* path) { delete static_cast<std::string*>(path); }  // frees the user data
);

if (task) {
    // Send it through the packet handle, once the engine is started: before
    // thryve_run_interactive_start (or thryve_service_run), the handle refuses it
    // with ThryveStatus_InvalidState. The send takes ownership of task, even when
    // it fails — do NOT call thryve_task_free on it afterward, that's a double-free.
    thryve_packet_handle_send_task(packet_handle, task);
}
```

### Sending a Notification

```cpp
// Create a notification
ThryveNotif notif = thryve_notification_create(
    "MyNotificationType",  // type
    "MyReceiver",          // receiver
    nullptr                // notif_core_ptr (optional)
);

if (notif) {
    // Send it through the packet handle, once the engine is started (the handle
    // refuses sends before that). The send takes ownership of notif — do NOT call
    // thryve_notification_free on it afterward, that's a double-free.
    ThryveStatus status = thryve_packet_handle_send_notification(packet_handle, notif);
    if (status != ThryveStatus_Ok) {
        std::cerr << "Failed to send notification: " << thryve_last_error() << std::endl;
    }
}
```

### Finding Out Why a Call Failed

A call that fails returns NULL or a status other than `ThryveStatus_Ok`, and `thryve_last_error()` says why, until the next Thryve call on the same thread:

```cpp
ThryveTask task = thryve_task_create("", 2, my_task_job, nullptr, nullptr);
if (!task) {
    std::cerr << "No task: " << thryve_last_error() << std::endl;
    // No task: task name must not be empty
}
```

### Starting the Engine

`thryve_run_interactive_start` spawns the engine on a background thread and returns immediately — it does not block. There is no separate "stop" FFI call: the engine's loop only exits once a task result comes back with `result_type = "Fin"` (or `"FinErr"`), which is what actually sets the engine's exit flag. `thryve_run_interactive_free` just waits (joins) for that to happen — call it too early (before any Fin task has been processed) and it blocks forever.

```cpp
// A task job that requests a graceful shutdown once submitted
extern "C" void shutdown_task_job(ThryveTaskResult* result, void*) {
    *result = thryve_task_result_new("Fin", "Shutting down", "Main");
}

// Start the interactive engine
std::cout << "Starting Thryve engine..." << std::endl;

ThryveRunHandle handle = thryve_run_interactive_start(ctx);
if (handle) {
    std::cout << "Engine started. Press Enter to stop..." << std::endl;
    std::cin.get();

    // Submit a shutdown task so the engine actually finalizes and its loop
    // exits — without this, thryve_run_interactive_free below would hang.
    ThryveTask shutdown_task = thryve_task_create("Shutdown", 0, shutdown_task_job, nullptr, nullptr);
    if (shutdown_task) {
        thryve_packet_handle_send_task(packet_handle, shutdown_task);
    }

    // Now safe to call — returns once the engine thread has processed the
    // shutdown task and exited its loop.
    thryve_run_interactive_free(handle);
}
```

### Complete Example (Interactive Mode)

```cpp
#include "thryve_ffi.h"
#include <iostream>

// Plugin callbacks
extern "C" int plugin_cleanup(const void* core_ptr) {
    std::cout << "Plugin cleanup" << std::endl;
    return ThryveStatus_Ok;
}

extern "C" void plugin_entry(ThryveTaskResult* result, void* core_ptr) {
    std::cout << "Plugin entry point" << std::endl;
    // Report that it started; leaving the result alone would report nothing
    *result = thryve_task_result_new("Started", "Plugin started", "Main");
}

// Observer callbacks
extern "C" void observer_cleanup(const void* core_ptr) {
    std::cout << "Observer cleanup" << std::endl;
}

extern "C" void observer_job(ThryveObserver obs) {
    std::cout << "Observer job started" << std::endl;
    while (ThryveNotif notif = thryve_observer_pop(obs)) {
        thryve_notification_free(notif);
    }
    std::cout << "Observer job stopped" << std::endl;
}

// Shutdown task job — the only way to make the engine's loop actually exit
extern "C" void shutdown_task_job(ThryveTaskResult* result, void*) {
    *result = thryve_task_result_new("Fin", "Shutting down", "Main");
}

int main() {
    // 1. Create configuration
    ThryveConfig config = thryve_config_default();
    if (!config) return 1;

    // 2. Create context
    ThryveCtx ctx = thryve_ctx_create(config);
    if (!ctx) {
        thryve_config_free(config);
        return 1;
    }

    // 3. Get the engine's connected PacketHandle from ctx — save it, it's
    // the only way to reach the engine once ctx is consumed in step 6.
    ThryvePacketHandle pkt = thryve_ctx_get_packet_handle(ctx);
    if (!pkt) {
        thryve_ctx_free(ctx);
        thryve_config_free(config);
        return 1;
    }

    // 4. Create and add plugin
    ThryvePlugin plugin = thryve_plugin_create(
        "MyType", nullptr, pkt, plugin_cleanup, plugin_entry
    );
    thryve_ctx_add_plugin(ctx, plugin);

    // 5. Create and add observer
    ThryveObserver obs = thryve_observer_create(
        "MyType", nullptr, pkt, observer_cleanup, observer_job
    );
    thryve_ctx_add_observer(ctx, obs);

    // 6. Start the engine. This consumes ctx — never touch or free ctx again
    // after this call.
    ThryveRunHandle handle = thryve_run_interactive_start(ctx);
    if (handle) {
        std::cin.get();

        // Submit a shutdown task so the engine actually finalizes and exits
        // its loop — without this, thryve_run_interactive_free below would hang.
        ThryveTask shutdown_task = thryve_task_create("Shutdown", 0, shutdown_task_job, nullptr, nullptr);
        if (shutdown_task) {
            thryve_packet_handle_send_task(pkt, shutdown_task);
        }

        thryve_run_interactive_free(handle);
    }

    // 7. Cleanup
    thryve_packet_handle_free(pkt);
    // NOTE: ctx was consumed by thryve_run_interactive_start, so don't free it
    // NOTE: plugin and observer are owned by ctx, so don't free them
    thryve_config_free(config);

    return 0;
}
```

## Running as a Windows Service

To run the Thryve engine as a Windows service, use `thryve_service_create` and `thryve_service_run` instead of `thryve_run_interactive_start`. The service mode is designed for background execution managed by the Windows Service Control Manager (SCM).

### Starting the Service

```cpp
// 1. Create configuration
ThryveConfig config = thryve_config_default();
if (!config) return 1;

// 2. Create the service instance. This also builds its matching ctx and
// returns both together — there's no separate thryve_ctx_create call for
// service mode, unlike interactive mode.
ThryveServiceCreateResult created = thryve_service_create(config);
if (!created.service || !created.ctx) {
    thryve_config_free(config);
    return 1;
}
ThryveService service = created.service;
ThryveCtx ctx = created.ctx;

// 3. Get the engine's connected PacketHandle from ctx (required to create
// plugins/observers)
ThryvePacketHandle pkt = thryve_ctx_get_packet_handle(ctx);
if (!pkt) {
    thryve_service_free(service);
    thryve_ctx_free(ctx);
    thryve_config_free(config);
    return 1;
}

// 4. Add plugins/observers to the context
// ... add plugin and observer as shown above ...

// 5. Start the service (blocks until SCM sends Stop)
// thryve_service_run is a BLOCKING call. It first sets the engine up (log folders,
// threads, observers, plugins), then registers with the Windows SCM. The engine
// starts processing when SCM sends Start, and thryve_service_run returns once SCM
// sends Stop. If the setup fails, or the process wasn't started by the SCM, it
// stops everything it started and returns an error status right away.
ThryveStatus status = thryve_service_run(service, ctx);
if (status != ThryveStatus_Ok) {
    std::cerr << "Service run failed: " << (int)status << std::endl;
}

// NOTE: After thryve_service_run returns, both `service` and `ctx` are already
// consumed (they become Box::from_raw inside thryve_service_run and are dropped).
// You do NOT call thryve_service_free or thryve_ctx_free after thryve_service_run.

// 6. Cleanup remaining resources
// Note: plugin is owned by ctx, so don't free it
// Note: ctx was consumed by thryve_service_run, so don't free it
// Note: service was consumed by thryve_service_run, so don't free it
thryve_packet_handle_free(pkt);
thryve_config_free(config);
```

### Service Lifecycle

The service lifecycle is managed by the Windows SCM:

1. **Setup**: Before it connects to the SCM, `thryve_service_run` sets the engine up:
   - Creates the log folders and files, and installs the panic hook
   - Starts the engine thread, the workers, the logger and the notification sorter
   - Loads observers and plugins from the context

   If a step fails, it stops what it already started, writes the error to `Error.log` (once the
   log folder exists) and returns `ThryveStatus_OperationFail` without connecting to the SCM.
2. **Start**: When the SCM sends `Command::Start`, the prepared engine starts its main processing
   loop. A second `Start` is logged and ignored.
3. **Stop**: When the SCM sends `Command::Stop`, the service:
   - Signals the engine to shut down
   - Joins the engine thread (ensures graceful cleanup)
   - Returns from `thryve_service_run`
4. **Pause/Resume**: When the SCM sends `Command::Pause` or `Command::Resume`, the engine suspends/resumes processing

If the process wasn't started by the SCM (for example, it was run from a console), connecting to
the SCM fails: `thryve_service_run` stops the prepared engine and returns
`ThryveStatus_InvalidState`.

### Installing and Uninstalling the Service

To install the service on Windows:

```bash
# Run as Administrator
ImgCompression.exe install
```

This uses `sc.exe` to register the service with the SCM. The service will start automatically on system boot.

To uninstall:

```bash
# Run as Administrator
ImgCompression.exe uninstall
```

This stops the service (if running) and removes it from the SCM.

### Service vs Interactive Mode Differences

| Aspect | Interactive | Service |
|--------|-------------|---------|
| Engine start | Immediate via `thryve_run_interactive_start` | Set up before connecting to the SCM; processing starts when SCM sends `Start` |
| Engine stop | You call `thryve_run_interactive_free` | SCM sends `Stop` command |
| Pause/Resume | Not supported | Supported via SCM |
| After run | **Don't** free `ctx` (consumed by start), free `config` | **Don't** free `ctx` (consumed by run), **don't** free `service` (consumed by run), free `config` |
| Blocking call | `thryve_run_interactive_start` returns `ThryveRunHandle` | `thryve_service_run` is blocking, returns `ThryveStatus` |

### Complete Example (Service Mode)

```cpp
#include "thryve_ffi.h"
#include <iostream>

// Plugin callbacks
extern "C" int plugin_cleanup(const void* core_ptr) {
    std::cout << "Plugin cleanup" << std::endl;
    return ThryveStatus_Ok;
}

extern "C" void plugin_entry(ThryveTaskResult* result, void* core_ptr) {
    std::cout << "Plugin entry point" << std::endl;
    *result = thryve_task_result_new("Started", "Plugin started", "Main");
}

int main() {
    // 1. Create configuration
    ThryveConfig config = thryve_config_default();
    if (!config) return 1;

    // 2. Create the service instance. This also builds its matching ctx and
    // returns both together — no separate thryve_ctx_create call needed here.
    ThryveServiceCreateResult created = thryve_service_create(config);
    if (!created.service || !created.ctx) {
        thryve_config_free(config);
        return 1;
    }
    ThryveService service = created.service;
    ThryveCtx ctx = created.ctx;

    // 3. Get the engine's connected PacketHandle from ctx
    ThryvePacketHandle pkt = thryve_ctx_get_packet_handle(ctx);
    if (!pkt) {
        thryve_service_free(service);
        thryve_ctx_free(ctx);
        thryve_config_free(config);
        return 1;
    }

    // 4. Create and add plugin
    ThryvePlugin plugin = thryve_plugin_create(
        "MyType", nullptr, pkt, plugin_cleanup, plugin_entry
    );
    thryve_ctx_add_plugin(ctx, plugin);

    // 5. Start the service (blocks until SCM sends Stop)
    ThryveStatus status = thryve_service_run(service, ctx);
    if (status != ThryveStatus_Ok) {
        std::cerr << "Service run failed: " << (int)status << std::endl;
    }

    // NOTE: After thryve_service_run returns, both `service` and `ctx` are already
    // consumed. You do NOT call thryve_service_free or thryve_ctx_free.

    // 6. Cleanup remaining resources
    thryve_packet_handle_free(pkt);
    thryve_config_free(config);

    return 0;
}
```

## Memory Management

### Ownership Rules

1. **Plugin/Observer creation**: After calling `thryve_plugin_create()` or `thryve_observer_create()`, the plugin/observer is yours until it's added to a context. Free one that's never added with `thryve_plugin_free()` or `thryve_observer_free()`.

2. **Context addition**: After calling `thryve_ctx_add_plugin()` or `thryve_ctx_add_observer()`, the plugin/observer is moved into the context's vectors. **Do not free it** — the context will clean it up.

3. **Observer job callback**: The `ThryveObserver` the job receives belongs to the engine, and stays valid until the job returns. **Don't free it** (on that observer, `thryve_observer_free()` does nothing) and don't keep it.

4. **PacketHandle**: Get it from `thryve_ctx_get_packet_handle(ctx)` — this is the engine's real, connected handle. (There is no standalone `thryve_packet_handle_create` — it doesn't exist, and a disconnected packet handle wouldn't reach the engine anyway.) It is cloned inside the Rust side when passed to plugin/observer creation, so you can continue to use your copy afterward.

5. **Sending tasks/notifications**: `thryve_packet_handle_send_task` and `thryve_packet_handle_send_notification` **take ownership** of the task/notification you pass in. **Do not** call `thryve_task_free`/`thryve_notification_free` on it afterward — that's a double-free. This holds even when the send fails: before the engine is started (by `thryve_run_interactive_start` or `thryve_service_run`), and once it's gone, they return `ThryveStatus_InvalidState` and drop what you passed in. So start the engine first, then send.

6. **`thryve_ctx_create` vs `thryve_service_create`**: `thryve_ctx_create(config)` is for **interactive mode** — it's the only way to get a bare `ctx` to populate before starting the engine. **Service mode doesn't use it** — `thryve_service_create(config)` already returns its own matching `ctx` bundled together with the service.

7. **User data, values and chunks**: given to Thryve with a plain task or a typed one, they're freed by Thryve, once, with the function given with each; typed tasks' handles are used up by every call that takes them. See [Writing Typed Tasks](#writing-typed-tasks).

8. **Strings**: names and other string arguments are copied, so you keep your strings.

### Service Mode Cleanup

When using `thryve_service_run`, **both** the service and context are **consumed** (not freed) inside the function. This is different from interactive mode where only `ctx` is consumed:

| Resource | Interactive (`thryve_run_interactive_start`) | Service (`thryve_service_run`) |
|----------|------------------------------------------|----------------------------|
| `ctx` | From `thryve_ctx_create` — consumed by start (don't free) | From `thryve_service_create`'s bundled result — consumed by run (don't free) |
| `service` | N/A | From `thryve_service_create` — consumed by run (don't free) |
| `config` | Free with `thryve_config_free` | Free with `thryve_config_free` |
| `packet_handle` | From `thryve_ctx_get_packet_handle(ctx)` — free with `thryve_packet_handle_free` | From `thryve_ctx_get_packet_handle(ctx)` — free with `thryve_packet_handle_free` |

**Important**: After `thryve_service_run` returns, you **must NOT** call:
- `thryve_service_free(service)` — the service was already consumed and dropped inside `thryve_service_run`
- `thryve_ctx_free(ctx)` — the ctx was already consumed and dropped inside `thryve_service_run`

Calling either of these after `thryve_service_run` will result in a **double-free** and undefined behavior.

### Ownership Transfer Diagram

```
Foreign Language                              Rust
────────────────                              ────
                                              ┌───────────────────────────┐
1. thryve_config_default()                    │ Creates and owns Config   │
   → ThryveConfig                             └───────────────────────────┘
                                              ┌───────────────────────────┐
2. thryve_ctx_create(config)                  │ Creates and owns Ctx      │
   → ThryveCtx                                └───────────────────────────┘
                                              ┌───────────────────────────┐
3. thryve_plugin_create(type, core, tx,       │ Copies type               │
   clean_up, entry_point)                     │ Wraps entry_point and     │
   → ThryvePlugin                             │ clean_up                  │
                                              │ Keeps plg_core_ptr for    │
                                              │ clean_up; never frees it  │
                                              └───────────────────────────┘
                                              ┌───────────────────────────┐
4. thryve_ctx_add_plugin(ctx, plugin)         │ Moves the plugin into ctx │
   → ThryveStatus                             │ Don't free it afterwards  │
                                              └───────────────────────────┘
```

## Troubleshooting

### Cannot find headers

Make sure the include path points to the directory containing `thryve_ffi.h`:

```bash
# CMake
target_include_directories(my_app PRIVATE ${CMAKE_SOURCE_DIR}/include)

# MSVC
cl /Iinclude main.cpp

# g++
g++ -Iinclude main.cpp
```

### Cannot link against thryve_ffi.lib

Make sure the library path is correct:

```bash
# CMake
target_link_directories(my_app PRIVATE ${CMAKE_SOURCE_DIR}/lib)
target_link_libraries(my_app PRIVATE thryve_ffi)

# MSVC
cl main.cpp /link lib/thryve_ffi.lib

# g++
g++ main.cpp -Llib -lthryve_ffi
```

### DLL not found at runtime (Windows)

Copy `thryve_ffi.dll` to the same directory as your executable:

```bash
# CMake (add to CMakeLists.txt)
add_custom_command(TARGET my_app POST_BUILD
    COMMAND ${CMAKE_COMMAND} -E copy_if_different
        ${CMAKE_SOURCE_DIR}/../dist/bin/thryve_ffi.dll
        $<TARGET_FILE_DIR:my_app>
)

# Manual
copy dist\bin\thryve_ffi.dll .
```

### Application crashes on startup

Ensure you're using the correct build configuration:
- Debug build: Use `dist/bin/thryve_ffi.dll` (or copy from `target/debug/thryve_ffi.dll`)
- Release build: Use `dist/bin/thryve_ffi.dll` (or copy from `target/release/thryve_ffi.dll`)

### IntelliSense errors in VS Code

Add the include directory to your `c_cpp_properties.json`:

```json
{
    "configurations": [
        {
            "name": "Win32",
            "includePath": [
                "${workspaceFolder}/**",
                "${workspaceFolder}/include"
            ],
            "defines": ["_DEBUG", "UNICODE", "_UNICODE"],
            "compilerPath": "C:/Program Files/Microsoft Visual Studio/2022/Community/VC/Tools/MSVC/14.37.32822/bin/Hostx64/x64/cl.exe",
            "cStandard": "c17",
            "intelliSenseMode": "windows-msvc-x64"
        }
    ],
    "version": 4
}
```

### Header files are out of date

Rebuild the FFI library:

```bash
cargo build --package thryve_ffi --release
```

The headers will be regenerated in the build's `OUT_DIR` and copied to `crates/thryve_ffi/out/`. A release's zip has them in `include/`.
